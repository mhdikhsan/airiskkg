PAIR-AI Semantic Web Guide

Panduan ini menjelaskan ontology dan knowledge graph di AI-RKG, lalu menunjukkan bagaimana sebuah use case menjadi input untuk metode PAIR-AI: dari architecture graph, motif matching, risk interpretation, sampai output candidate risk graph.

1. Ontology vs Knowledge Graph

Untuk pemula semantic web, bedakan dua hal ini dulu:

Ontology

Ontology adalah vocabulary atau schema. Ia mendefinisikan class, property, dan hubungan konseptual yang boleh dipakai.

Contoh: beam:System, beam:Data, pair:GraphMotif, pair:RiskFinding, pair:playsRole.

Knowledge Graph

Knowledge graph adalah kumpulan triple RDF aktual. Ia berisi instance dan fakta yang memakai vocabulary dari ontology.

Contoh: uc6:LLMPrompting a beam:Transform, uc6:LLMPrompting pair:playsRole pair:GenerationStep, atau sebuah generated finding bertipe pair:RiskFinding.

Di repo ini, ontology adalah file schema/vocabulary seperti ontology/core/*.ttl. Knowledge graph adalah graph yang dibangun dari gabungan ontology, taxonomy, motif library, risk pattern, use-case architecture graph, dan hasil generated output.

2. Ontology Di AI-RKG

AI-RKG kamu sekarang bisa dibaca sebagai tiga modul konseptual: architecture module, risk module, dan PAIR-AI pattern module. Di luar itu ada library motif, interpretation layer, taxonomy KB, dan output assessment.

Bagian File utama Fungsi
Architecture module ontology/core/beam_core.ttl Vocabulary untuk menggambar struktur sistem AI: system, data, model, process, agent, dan flow seperti beam:use, beam:produce, beam:inform.
Risk module ontology/core/beam_core_risk.ttl Vocabulary risiko umum: beamr:Risk, beamr:RiskControl, consequence, impact, dan relasi risk-control.
PAIR-AI pattern module ontology/core/pair_ai_pattern.ttl Vocabulary metode PAIR-AI untuk role annotation, graph motif, motif match, risk interpretation, executable OQP, dan generated risk finding.
Motif library ontology/patterns/motif.ttl Library motif arsitektur reusable. Contoh: pat:VectorBasedInformationRetrievalMotif.
Risk interpretation library ontology/patterns/risk_pattern_library.ttl Library AI risk pattern: bridge dari motif ke risk knowledge: condition, mechanism, candidate taxonomy entries, suggested controls, dan query implementation.
Taxonomy KB ontology/taxonomy/*.ttl Knowledge dari OWASP LLM, MIT AI Risk, IBM Risk Atlas, MIT controls, dan mapping antar taxonomy.
Use-case graph ontology/example/uc6_onlim.ttl Instance graph untuk sistem yang mau di-assess. Ini input utama PAIR-AI untuk satu use case.

Yang Mana Knowledge Graph-nya?

Ada beberapa level graph:

  • Reusable AI-RKG: gabungan core ontology, taxonomy KB, motif library, dan risk pattern library.
  • Architecture graph: use-case-specific graph, misalnya uc6_onlim.ttl.
  • Working graph: graph runtime yang diload oleh runner: reusable AI-RKG + architecture graph + generated motif matches.
  • Candidate risk graph: output assessment, yaitu pair:RiskFinding dan relasinya ke evidence, mechanism, taxonomy entry, condition, dan controls.

3. Proses Besar: Jangan Dicampur

AI-RKG Construction

Ini proses membangun reusable knowledge sebelum assessment dijalankan. Output-nya adalah ontology, taxonomy KB, motif library, risk pattern, dan SPARQL OQP template.

  • Ekstraksi risk content dari OWASP, MIT, IBM.
  • Alignment taxonomy dengan SKOS mapping.
  • Curation motif arsitektur.
  • Curation risk interpretation.
  • Encoding query SPARQL CONSTRUCT.

PAIR-AI Assessment

Ini proses memakai reusable AI-RKG untuk menilai satu architecture graph tertentu.

  • Load architecture graph use case.
  • Match motif arsitektur.
  • Apply risk interpretation condition.
  • Derive risk mechanism.
  • Construct candidate risk graph.

4. Alur PAIR-AI Di Repo

Architecture graph -> role/data annotation -> motif matching query -> pair:MotifMatch -> risk interpretation query -> pair:RiskFinding -> candidate risk graph

Implementasi runtime-nya ada di python/src/airiskkg/assessment_runner.py. Intinya: 

load core ontology
load pattern library
load taxonomy KB
load use-case architecture graph

for each implementation producing pair:MotifMatch:
    run SPARQL CONSTRUCT
    merge motif matches into working graph

for each implementation producing pair:RiskFinding:
    run SPARQL CONSTRUCT
    merge risk findings into working graph

write outputs

5. Membuat Architecture Graph Sebagai Input

Untuk membangun use case baru, buat file TTL berisi instance sistem. Minimalnya, graph harus punya:

  1. System instance: a beam:System.
  2. Resource: data, model, prompt, output.
  3. Process: retrieval, embedding, generation, transform, infer.
  4. Flow: beam:use, beam:produce, beam:inform.
  5. Role annotation: pair:playsRole.
  6. Data category annotation: pair:containsDataCategory.
  7. Optional represented control: control dengan beamr:associatedTo.

Contoh minimal: 

@prefix ex:    <http://w3id.org/airiskkg/example/my-use-case#> .
@prefix beam:  <http://w3id.org/beam/core#> .
@prefix pair:  <http://w3id.org/airiskkg/pair-ai#> .
@prefix rdfs:  <http://www.w3.org/2000/01/rdf-schema#> .

ex:MySystem
    a beam:System ;
    rdfs:label "My AI system"@en ;
    beam:hasResource ex:UserQuestion, ex:VectorDB, ex:RetrievedContext, ex:LLM, ex:Answer ;
    beam:hasProcess ex:RetrievalStep, ex:GenerationStep .

ex:UserQuestion
    a beam:Data ;
    pair:playsRole pair:PublicUserInput ;
    pair:containsDataCategory pair:ExternalUserContent ;
    beam:usedBy ex:RetrievalStep .

ex:VectorDB
    a beam:Data ;
    pair:playsRole pair:VectorStore ;
    pair:containsDataCategory pair:SensitiveInformation ;
    beam:usedBy ex:RetrievalStep .

ex:RetrievedContext
    a beam:Data ;
    pair:playsRole pair:RetrievedContext ;
    pair:containsDataCategory pair:SensitiveInformation ;
    beam:usedBy ex:GenerationStep .

ex:LLM
    a beam:StatisticalModel ;
    pair:playsRole pair:GenerativeModel ;
    beam:usedBy ex:GenerationStep .

ex:Answer
    a beam:Data ;
    pair:playsRole pair:PublicUserFacingOutput .

ex:RetrievalStep
    a beam:Infer ;
    pair:playsRole pair:RetrievalStep ;
    beam:use ex:UserQuestion, ex:VectorDB ;
    beam:produce ex:RetrievedContext ;
    beam:inform ex:GenerationStep .

ex:GenerationStep
    a beam:Transform ;
    pair:playsRole pair:GenerationStep ;
    beam:use ex:RetrievedContext, ex:LLM ;
    beam:produce ex:Answer .
Di paper, role annotation bisa dibantu LLM. Di repo sekarang, annotation seperti pair:playsRole pair:VectorStore dan pair:containsDataCategory pair:SensitiveInformation ditulis langsung di TTL. Jadi prototype ini mengasumsikan architecture graph sudah role-annotated.

6. Bagaimana Motif Library Dipanggil?

Motif library mendefinisikan motif secara konseptual. Contoh di ontology/patterns/motif.ttl: 

pat:VectorBasedInformationRetrievalMotif
    a pair:GraphMotif ;
    pair:hasPatternNode
        pat:VectorIR_QueryNode,
        pat:VectorIR_VectorStoreNode,
        pat:VectorIR_RetrievalStepNode,
        pat:VectorIR_RetrievedResultNode ;
    pair:hasPatternEdge
        pat:VectorIR_RetrievalUsesQueryEdge,
        pat:VectorIR_RetrievalUsesVectorStoreEdge,
        pat:VectorIR_RetrievalProducesResultEdge ;
    pair:implementedBy pat:VectorIR_MatchingOQP .

Lalu risk_pattern_library.ttl mencatat file query executable: 

pat:VectorIR_MatchingOQP
    a pair:PatternImplementation ;
    pair:implementsMotif pat:VectorBasedInformationRetrievalMotif ;
    pair:implementationPath "ontology/patterns/implementation/match_vector_ir.rq" ;
    pair:producesOutputType pair:MotifMatch .

Runner mencari semua pair:PatternImplementation yang pair:producesOutputType pair:MotifMatch, membaca pair:implementationPath, lalu menjalankan query tersebut. Jadi motif library tidak dipanggil manual satu-satu; ia dipanggil lewat metadata RDF.

7. Query CONSTRUCT Untuk Motif Match

Query motif matching berada di ontology/patterns/implementation/match_vector_ir.rq. Bentuk sederhananya: 

CONSTRUCT {
    ?match
        a pair:MotifMatch ;
        pair:matchesMotif pat:VectorBasedInformationRetrievalMotif ;
        pair:hasNodeBinding ?queryBinding, ?retrievalBinding, ?vectorStoreBinding, ?resultBinding .

    ?queryBinding
        a pair:NodeBinding ;
        pair:bindsPatternNode pat:VectorIR_QueryNode ;
        pair:matchedElement ?query .
}
WHERE {
    ?retrievalStep
        beam:use ?query ;
        beam:use ?vectorStore ;
        beam:produce ?retrievedResult ;
        pair:playsRole/pair:subRoleOf* pair:RetrievalStep .

    ?query pair:playsRole/pair:subRoleOf* pair:UserInput .
    ?vectorStore pair:playsRole/pair:subRoleOf* pair:VectorStore .
    ?retrievedResult pair:playsRole/pair:subRoleOf* pair:RetrievedContext .
}

Bagian WHERE mencari struktur di architecture graph. Bagian CONSTRUCT membuat graph baru berisi pair:MotifMatch dan pair:NodeBinding.

Output tahap ini ditulis ke: 

outputs/motif_matches.ttl

8. Memasukkan Condition Untuk Derive Risk Mechanism

Motif tidak otomatis berarti risk. Motif baru menjadi risk-relevant jika condition tertentu terpenuhi.

Condition dan interpretation didefinisikan di ontology/patterns/risk_pattern_library.ttl: 

pat:SensitiveDataRetrievalExposureInterpretation
    a pair:MotifInterpretation ;
    pair:interpretsMotif pat:VectorBasedInformationRetrievalMotif ;
    pair:interpretedAsMechanism owasp:mechanism-sensitive-data-propagation ;
    pair:hasInterpretationCondition
        pat:VectorIR_SensitiveRetrievedContextCondition,
        pat:VectorIR_ContextEntersLLMGenerationCondition,
        pat:VectorIR_NoRepresentedDisclosureControlCondition ;
    pair:mayIndicateRisk
        owasp:llm02-sensitive-information-disclosure,
        atlas:exposing-personal-information,
        mit:subdomain-2-1 ;
    pair:suggestedControl
        mitctrl:privacy-control-for-user-data,
        mitctrl:redaction,
        mitctrl:input-output-filtering ;
    pair:implementedBy pat:SensitiveDataRetrievalExposureOQP .

Risk mechanism di sini bukan dibuat saat assessment. Mechanism sudah ada di knowledge base, misalnya: 

owasp:mechanism-sensitive-data-propagation

Saat assessment, query hanya memilih mechanism itu karena motif match dan condition-nya terpenuhi.

9. Risk Interpretation Juga Lewat Query

Ya, risk interpretation juga dieksekusi lewat SPARQL CONSTRUCT. Contohnya ada di ontology/patterns/implementation/risk_sensitive_retrieval.rq.

Query ini melakukan tiga hal:

  1. Membaca pair:MotifMatch yang sudah dibuat.
  2. Mengecek condition tambahan di architecture graph.
  3. Membuat pair:RiskFinding.
WHERE {
    ?match
        a pair:MotifMatch ;
        pair:matchesMotif pat:VectorBasedInformationRetrievalMotif ;
        pair:hasNodeBinding ?queryBinding, ?retrievalBinding, ?vectorStoreBinding, ?resultBinding .

    ?retrievedResult pair:containsDataCategory/pair:subDataCategoryOf* pair:SensitiveInformation .

    ?generationStep
        beam:use ?retrievedResult ;
        beam:use ?llm ;
        beam:produce ?userFacingOutput ;
        pair:playsRole/pair:subRoleOf* pair:GenerationStep .

    FILTER NOT EXISTS {
        pat:SensitiveDataRetrievalExposureInterpretation
            pair:suggestedControl ?implementedDisclosureControl .
        ?implementedDisclosureControl beamr:associatedTo ?controlledElement .
    }
}

Bagian FILTER NOT EXISTS dipakai untuk mendeteksi bahwa control yang disarankan belum direpresentasikan pada elemen evidence. Ini bukan bukti bahwa control benar-benar tidak ada di dunia nyata; ini hanya berarti control tidak terlihat di architecture graph yang diberikan.

10. Output Assessment

Output utama PAIR-AI adalah candidate risk graph. Di repo ini output-nya:

File Isi
outputs/motif_matches.ttl Hasil motif matching: pair:MotifMatch dan pair:NodeBinding.
outputs/risk_findings.ttl Candidate risk graph: pair:RiskFinding beserta evidence, mechanism, taxonomy, condition, dan suggested controls.
outputs/combined_assessment_graph.ttl Working graph lengkap setelah core, patterns, taxonomy, architecture graph, motif matches, dan risk findings digabung.

Contoh struktur finding: 

?riskFinding
    a pair:RiskFinding ;
    pair:generatedFromMatch ?match ;
    pair:generatedByMotif pat:VectorBasedInformationRetrievalMotif ;
    pair:hasInterpretedMechanism owasp:mechanism-sensitive-data-propagation ;
    pair:hasEvidenceElement ?retrievalStep, ?vectorStore, ?retrievedResult, ?llm, ?userFacingOutput ;
    pair:hasCandidateRiskTaxonomyEntry owasp:llm02-sensitive-information-disclosure ;
    pair:hasSuggestedControl mitctrl:redaction ;
    pair:hasSatisfiedCondition pat:VectorIR_SensitiveRetrievedContextCondition ;
    pair:findingStatus "candidate" .

11. Checklist Membuat Use Case Baru

  1. Buat file baru di ontology/example/, misalnya my_system.ttl.
  2. Definisikan system, resources, processes, model, input, output.
  3. Hubungkan flow dengan beam:use, beam:produce, dan beam:inform.
  4. Tambahkan role annotation dengan pair:playsRole.
  5. Tambahkan data category dengan pair:containsDataCategory.
  6. Jika ada represented control, tambahkan control dan hubungkan dengan beamr:associatedTo.
  7. Pastikan motif query yang ada bisa match. Kalau belum, tambah motif dan query baru.
  8. Tambahkan interpretation jika motif baru punya risk mechanism/condition baru.
  9. Jalankan assessment runner dan cek outputs/*.ttl.
Runner sekarang bisa menerima satu atau beberapa file architecture graph dari CLI. Jika tidak diberi path, default-nya tetap memakai contoh ontology/example/uc6_onlim.ttl.

12. Ringkasan Mental Model

Ontology = vocabulary/schema: beam, beamr, pair, nexus, taxonomy classes Reusable AI-RKG = ontology + taxonomy KB + motif library + risk pattern library Architecture graph = instance graph dari sistem yang mau dinilai Motif matching = SPARQL CONSTRUCT membuat pair:MotifMatch Risk interpretation = SPARQL CONSTRUCT mengecek condition dan membuat pair:RiskFinding Candidate risk graph = output system-specific yang menjelaskan risk, evidence, mechanism, taxonomy, controls

Generated for the AI-RKG / PAIR-AI repository. This document describes the current implementation shape, where role annotation is represented explicitly in TTL and may later be produced manually or with LLM assistance.
